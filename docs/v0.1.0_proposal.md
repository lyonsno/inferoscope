# inferoscope v0.1.0 Proposal

Updated: 2026-03-18

## Project Brief

Build a replay-first, one-token-complete WebGPU instrument for `allenai/OLMoE-1B-7B-0125` that captures full per-layer routing for each generated token, derives provisional global and local motif assignments, and renders them in a restrained 3D stack with audit handles always close at hand.

The goal of `v0.1.0` is not semantic interpretation. The goal is to make recurring routing identities visible without losing access to the raw substrate.

## Core Constraints

- Render one token behind generation so the full routing event is known before classification or display.
- Treat a completed token event as the primary object, not a stream of partial activations.
- Keep raw routing data and derived motif hypotheses separate.
- Preserve auditability: any visible pattern should be inspectable back to raw routing values.
- Avoid forcing coherence. If the data does not stabilize a clean motif, the instrument should show weak fit or novelty rather than invent a confident story.

## First Model Target

- Initial real telemetry source: `allenai/OLMoE-1B-7B-0125`
- Expected follow-up validation targets after the first end-to-end pass:
  - `Qwen/Qwen3-30B-A3B`
  - likely `Qwen/Qwen3.5-35B-A3B`

`OLMoE-1B-7B-0125` is the first target because it is small enough for fast iteration while still having a representative sparse routing shape.

## Deliverable Shape

`v0.1.0` is replay-first, not live-first.

It should produce:

- a raw run artifact with exact token sequence and full routing traces,
- a derived artifact with provisional motif assignments and fit/novelty signals,
- and a viewer that replays those artifacts with scrub, pause, speed control, raw inspection, and scramble mode.

Live websocket streaming is intentionally deferred until the replay path is honest and useful.

## Artifacts

Each captured run should live under `runs/<run_id>/`.

Planned first artifacts:

- `manifest.json`
- `raw_trace.ndjson`
- `derived.ndjson`
- `motif_ledger.json`
- `contingency.json`
- `layout.json`

Notes:

- `manifest.json` records model id, tokenizer id, prompt, seed, generation parameters, capture settings, schema versions, and derivation versions.
- `raw_trace.ndjson` stores completed-token routing events.
- `derived.ndjson` stores derived outputs from the raw trace.
- `motif_ledger.json` stores motif centroids, thresholds, counts, and derivation metadata.
- `contingency.json` stores simple token-to-motif and motif-to-token summaries plus derivation metadata.
- `layout.json` stores viewer layout positions separately from the raw trace so geometry changes do not invalidate capture artifacts.

## Version Precedence

Version identity should not be split across filenames, payloads, and manifests with no precedence rule.

For `v0.1.0`:

- in-payload `schema_version` fields are authoritative for validation,
- filenames are storage conventions only and must not be treated as version authority,
- `manifest.json` records the versions a run bundle expects and loaders should reject bundles whose payload versions do not match the manifest.

This is why artifact filenames above avoid embedding schema-version identity.

## Raw Trace Contract

The core event should be `token_complete`.

Do not make the viewer depend on partial layer updates for `v0.1.0`.

Example shape:

```json
{
  "event_type": "token_complete",
  "schema_version": "raw/v0.1.0",
  "run_id": "2026-03-18_olmoe_demo_001",
  "token_index": 17,
  "token_id": 29871,
  "token_text": "ing",
  "context_length": 143,
  "timing_ms": {
    "decode_start": 812.4,
    "decode_end": 839.8,
    "decode_duration": 27.4
  },
  "layers": [
    {
      "layer_index": 0,
      "layer_kind": "moe",
      "num_total_experts": 8,
      "num_active_experts": 8,
      "router_probs": [0.221, 0.183, 0.141, 0.128, 0.109, 0.087, 0.075, 0.056],
      "topk_indices": [0, 1, 2, 3, 4, 5, 6, 7],
      "topk_probs": [0.221, 0.183, 0.141, 0.128, 0.109, 0.087, 0.075, 0.056],
      "entropy": 2.017,
      "normalized_entropy": 0.970,
      "top1_prob": 0.221,
      "top1_top2_margin": 0.038
    }
  ]
}
```

The example above uses `8` experts only to keep the JSON readable. Real `OLMoE-1B-7B-0125` captures in `v0.1.0` should emit `64` router probabilities per sparse layer.

`router_probs` should store the full expert routing distribution in `v0.1.0` for auditability.

Raw-event invariants:

- `router_probs` length must equal `num_total_experts`.
- `topk_indices` length must equal `topk_probs` length.
- `topk_indices` and `topk_probs` length must each equal `num_active_experts`.
- `router_probs` should sum to `1.0` within a small floating-point tolerance.
- `topk_probs` should equal `router_probs` at the corresponding `topk_indices`, subject to the same floating-point tolerance.

Some of these invariants are semantic rather than purely structural. `v0.1.0` should use JSON Schema for artifact shape and version enforcement, and a separate semantic validation layer for replay-critical cross-field and cross-file checks.

`routing_sharpness` is not a separate raw field. The viewer or derivation layer can compute it as:

```text
entropy = -sum_i p_i ln(p_i)
normalized_entropy = entropy / ln(num_total_experts)
routing_sharpness = 1 - normalized_entropy
```

Use natural logarithms for both `entropy` and `normalized_entropy`. This avoids smuggling a fuzzy interpretation into the raw trace while still making the normalization basis explicit.

## Derived Contract

Derived outputs in `v0.1.0` should be treated as provisional.

The canonical `v0.1.0` schema only fixes the derived-event envelope, not the internal motif payload structure or scoring semantics. This keeps the raw contract testable now without pretending that fingerprint hashing, motif similarity, fit scoring, or novelty scoring have already stabilized.

Example shape:

```json
{
  "event_type": "token_derived",
  "schema_version": "derived/v0.1.0-provisional",
  "run_id": "2026-03-18_olmoe_demo_001",
  "token_index": 17,
  "derivation_version": "motifs/v0.1.0-alpha",
  "derivation_config_id": "motifs/default-alpha",
  "derived_payload": {
    "global_motif": {
      "motif_id": "g_012"
    },
    "layer_motifs": [
      {
        "layer_index": 0,
        "motif_id": "l00_004"
      }
    ]
  }
}
```

For `v0.1.0`, fields such as `fingerprint_hash`, `fit_score`, and `novelty_score` are intentionally not part of the canonical derived schema contract yet.

## First Derivation Approach

`v0.1.0` should use a deliberately humble motifing pass.

- Layer fingerprint: the full routing probability vector for a single layer on a single token.
- Token fingerprint: the concatenation of all layer routing vectors for a completed token.
- Local motifs: per-layer, per-run online clustering with a conservative similarity threshold.
- Global motifs: per-run online clustering over full token fingerprints.
- Fit score: deferred from the canonical schema until the similarity metric and score domain are fixed.
- Novelty score: deferred from the canonical schema until its relationship to fit score and its score domain are fixed.
- No cross-run motif identity claims in `v0.1.0`.
- No semantic labels in `v0.1.0`.

Every derived artifact should carry a `derivation_version` and enough config metadata to reproduce or compare runs later, even while the payload remains provisional.

## Viewer Requirements

The viewer must:

- replay completed token events deterministically,
- support pause, scrub, step, and variable playback speed,
- render one global motif channel and one local motif channel separately,
- surface weak fit and novelty clearly,
- provide quick access to the raw per-layer routing basis for any displayed event,
- support a scramble mode that runs through the same rendering path,
- and keep expert positions stable throughout a run.

The viewer must not:

- claim semantic meaning for motifs,
- pretend motif ids are universal across runs or models,
- depend on expert reordering to be useful,
- or collapse into a purely aesthetic scene with no quick path back to the substrate.

## Visual Form

The first visual form should be a restrained 3D layer stack.

- Each layer uses fixed expert positions from `layout.json`.
- Global motif identity controls a broad color vocabulary such as halo or scene wash.
- Local motif identity controls layer or expert-level accent color.
- `routing_sharpness` can drive pulse tightness, bloom, or other concentration-related cues.
- Novelty should use a separate visual channel from motif color so novelty does not masquerade as category.

This is a 3D first pass for engagement, not a claim that 3D has already earned semantic authority.

## Anti-Bullshit Handles Required In v0.1.0

- Raw substrate inspection
- Replay
- Scramble mode
- Fit / ambiguity visibility
- Novelty visibility

Comparison tooling should be considered important, but full side-by-side comparison can land after the first replay-first pass if needed.

## Architecture Decisions To Lock Early

- The canonical schema should live in the repo root under `schema/`.
- Raw trace capture, derived motifing, and rendering should remain separate layers.
- Layout should be external to traces so geometry changes do not rewrite historical data.
- The renderer should consume run bundles rather than model-specific objects.
- Palette registries for global motifs and local motifs should be separate.
- For `v0.1.0`, only the raw trace, manifest, and layout contracts should be treated as stable test targets; derived artifacts remain explicitly provisional.
- JSON Schema and semantic validation should be treated as complementary layers: schema for artifact shape, semantic validation for replay/provenance invariants that span fields or files.

## Non-Goals For v0.1.0

- Live streaming
- Cross-run motif identity
- Semantic labeling
- Expert geography derived from co-activity
- Flow / alluvial views
- Hybrid/shared-expert-specific rendering

## Acceptance Bar

`v0.1.0` is successful if:

- a real `OLMoE` run can be captured and replayed deterministically,
- recurring local and global routing structures become visibly noticeable,
- visible patterns can be interrogated back to raw routing values quickly,
- scramble mode looks materially less coherent than the real run on at least some prompts,
- and weak motif assignments remain visibly weak instead of falsely authoritative.
